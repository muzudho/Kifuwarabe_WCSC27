# 🏗️ アーキテクチャ

きふわらべい（Kifuwarakei）の設計思想とアーキテクチャについて説明するぜ（＾▽＾）！

## 🎯 設計コンセプト

### Unity 対応を見据えたクリーンアーキテクチャ

このプロジェクトは、将来的に **Unity で動作させることを目指して** クリーンアーキテクチャを採用しています。

- **プラットフォーム非依存** にするため、レイヤー分けを徹底
- **Macユーザーでも遊べる** ようにするのが目標
- コンソール（Windows）版と Unity 版で **ロジックを共有**

## 📦 レイヤー構成

```plaintext
┌─────────────────────────────────────┐
│  Sources/Engine (プレゼンテーション層)  │  ← USIプロトコル、コンソールUI
│  - Program.cs                        │
│  - EngineConf.cs                     │
└─────────────────────────────────────┘
			  ↓ 依存
┌─────────────────────────────────────┐
│  Sources/UseCases (ユースケース層)    │  ← ゲームのルール、コマンド処理
│  - Playing.cs                        │
│  - PlayingSupport.cs                 │
└─────────────────────────────────────┘
			  ↓ 依存
┌─────────────────────────────────────┐
│  Sources/Entities (エンティティ層)    │  ← 駒、盤面、ビットボードなど
│  - 駒、盤面の定義                     │
│  - ビットボード演算                   │
│  - 局面ハッシュ                       │
└─────────────────────────────────────┘
```

### 各レイヤーの役割

#### 🎮 **Engine (プレゼンテーション層)**
- **責務**: ユーザーとの接点、入出力
- **含まれるもの**:
  - `Program.cs`: エントリーポイント
  - `EngineConf.cs`: 設定管理
  - USIプロトコルのコマンド受付
  - どうぶつしょうぎモードのコンソールUI

#### 🎯 **UseCases (ユースケース層)**
- **責務**: ゲームのルール、アプリケーションロジック
- **含まれるもの**:
  - `Playing.cs`: 対局の進行制御
  - 指し手の生成・検証
  - 思考ルーチン
  - コマンド処理ロジック

#### 🧱 **Entities (エンティティ層)**
- **責務**: 将棋の基本要素、ドメインモデル
- **含まれるもの**:
  - 駒の定義 (Med_Koma.cs など)
  - 盤面の表現
  - ビットボード演算
  - 局面ハッシュ (KyokumenHashImpl.cs)
  - 定跡管理 (JosekiImpl.cs)

## 🎲 ビットボード設計

### 128bit ビットボード

きふわらべいの最大の特徴は **128bit のビットボード** を使っていることだぜ（＾▽＾）！

```plaintext
対応可能な盤面サイズ: 3x4 盤 ～ 9x9 盤

例:
- 3x4 盤: どうぶつしょうぎ
- 5x5 盤: 5五将棋
- 9x9 盤: 本将棋
```

### なぜ128bit？

- 通常の64bit ビットボードだと 8x8 (64マス) が限界
- 9x9 盤 (81マス) をカバーするために 128bit を採用
- さらに拡張性を持たせて、変則将棋にも対応可能

### ビットボードの利点

✅ 高速な盤面操作（ビット演算）  
✅ 利き判定が高速  
✅ メモリ効率が良い  

## 🧩 主要なコンポーネント

### 📌 駒 (Koma)

`Sources/Entities/Features/abstracts/Med_Koma.cs`

- 駒の種類、動き、成りなどを定義
- ビットボード形式で駒の配置を管理

### 📌 局面 (Kyokumen)

盤面の状態を表現するクラス。

- 現在の駒の配置
- 手番 (先手/後手)
- 持ち駒
- 局面ハッシュ

### 📌 指し手生成

`UseCases` レイヤーで実装。

- 合法手の列挙
- 王手判定
- 詰み判定

### 📌 定跡 (Joseki)

`Sources/Entities/Features/implements/JosekiImpl.cs`

- 定跡データの読み込み・検索
- **注意**: 現在は 3x4 盤専用で、他のサイズでは動作しません

### 📌 機械学習

**注意**: 現在は機能停止中です（＾～＾）

- 元々は 3x4 盤専用の機械学習機能があった
- 設計変更により動かなくなった

## 🔄 動作フロー

### USIモード

```plaintext
1. 将棋所から USI コマンド送信
   ↓
2. Engine (Program.cs) が受信
   ↓
3. UseCases (Playing.cs) でコマンド処理
   ↓
4. Entities のビットボードで盤面更新
   ↓
5. 思考エンジンが最善手を計算
   ↓
6. USI形式で指し手を返却
   ↓
7. 将棋所で駒が動く
```

### どうぶつしょうぎモード

```plaintext
1. コンソールでコマンド入力
   ↓
2. Engine が受信
   ↓
3. UseCases でコマンド処理
   ↓
4. Entities で盤面更新
   ↓
5. コンソールに結果を表示
```
